# Plan: Remove comments

Requirement: [task.md](task.md)
Status: Done

## Summary
A one-off, lexer-aware Python script removes every comment from the in-scope files. It understands strings,
raw strings and char literals, so text that only looks like a comment is never touched. The script runs one
area at a time (shared core, cmp, native-android, native-ios, config) and each area is compiled before moving
on. ktlint auto-correct then tidies the blank lines that removed comments leave in Kotlin; the script tidies
them in the other file types. Finally the "no comments" convention is written into CLAUDE.md and the rules.
The same script in `--check` mode proves that no comments remain, and a diff check proves that only comments
were removed.

## Decisions
- One-off Python script in the session scratchpad, not committed — the user chose a script over hand edits.
  It covers about 200 files consistently. Hand edits were rejected as slow and easy to get wrong.
- Material Icons license notes in drawables (`ic_person.xml` ×2, `ic_arrow_back.xml`) are removed like any
  other comment — user's choice. Keeping them as a legal exception was rejected.
- `// Generated by tmdb.module. Do not edit.` in the `TmdbSecrets` source template
  (`build-logic/.../TmdbSecrets.kt`) is removed — user's choice. This is a deliberate exception to EC-1
  (comment-like text inside strings stays unchanged). `// swift-tools-version:$SWIFT_TOOLS` in the
  `Package.swift` template stays: SwiftPM requires it.
- One PR with one commit per area (steps 2–7) — user's choice, for easier review. `forge` does not commit,
  so the commits are made afterwards along the step boundaries. A single commit was rejected as too large
  to review.
- Tool directives (`ktlint-disable`, `noinspection`, `swiftlint:`, `MARK:`, `@formatter`): the inventory
  finds none. The script keeps any it meets and reports them instead of removing them.
- Files edited only by hand, by their tool, or not at all: `*.pbxproj`, `*.xcscheme`, `*.plist`,
  `Package.resolved`, `*.xcstrings`, `gradlew`, `gradlew.bat`, `gradle/wrapper/**`, `*.example`, `*.md`,
  binaries and JSON/SVG (no comment syntax or none present).

## Steps
### Step 1: Write the comment-stripping script  (AC-1, AC-2, EC-1, EC-4, EC-5) ✅
- Files: `<scratchpad>/strip_comments.py` (new, not committed).
- What:
  - CLI: `strip_comments.py (--check | --apply) <paths...>`. `--check` prints `path:line: <comment>` for every
    comment found and exits 1 if there are any. `--apply` rewrites files in place and prints what it removed.
  - Picks a lexer from the file extension and refuses unknown extensions:
    - `kt`/`kts`/`swift`: `//…` to end of line, `/* … */` and `/** … */` with nesting, skipped while inside
      `"…"` (escapes, `${…}`/`\(…)` templates that can hold nested strings), `"""…"""` raw/multi-line
      strings and `'…'` char literals.
    - `sq`: `--…` and `/* … */` outside `'…'` literals.
    - `xml`: `<!-- … -->`.
    - `toml`, `yml`, `properties`, `gitignore`, `sh`: whole lines whose first non-blank character is `#`. Keeps
      line 1 of a `.sh` file when it starts with `#!`. The inventory finds no trailing `#` comments in these
      types, so the script reports any it sees instead of guessing.
  - Directives (`ktlint`, `noinspection`, `swiftlint:`, `MARK:`, `@formatter`, `language=`): kept and reported.
  - Layout after removal:
    - A line left with only whitespace is dropped.
    - A trailing comment loses the comment and the spaces before it, and the code stays on its line.
    - Where a dropped comment sat between two blank lines, one blank line remains.
    - Leading blank lines in a file are removed.
- Pseudo-code (Kotlin raw string end): inside `"""`, the string ends at the first run of three or more quotes,
  and the last three quotes of that run close it (`"""name: "SQLCipher""""` holds `name: "SQLCipher"`).
- Dry run: `--check` over the in-scope file list (below). Compare its output with the inventory:
  - ~273 KDoc blocks in Kotlin;
  - the comment lines listed in Changes overview;
  - no hits in `architecture-test/build.gradle.kts` lines 24–25 (`"**/*.kt"`), `SqlCipher.kt:48`, or any
    `https://` string;
  - the `// swift-tools-version` and `// Generated by` template lines are not reported (they are strings).
- In-scope file list:
  `git ls-files | grep -vE '\.(md|pbxproj|xcscheme|plist|resolved|xcstrings|json|svg|png|jar|bat|example)$|(^|/)gradlew$|gradle/wrapper/'`
- Compile: none (no repository change).

## Out of scope
- Automated enforcement of the no-comments rule (task.md: out of scope).
- Moving removed explanations into docs or renaming code to replace them (task.md: out of scope).
- Committing the script; it stays in the scratchpad.
- Committing and opening the PR: done after `forge`, one commit per Step 2–7.

## Risks
- A lexer bug corrupts code inside a string (e.g. a raw string ending in `""""`). Mitigation: the Step 1 dry
  run is compared with the inventory before anything changes, each area is compiled right after it is
  changed, and the full test suites run in Step 8.
- Swift has no formatter, so leftover blank lines go unnoticed. Mitigation: the script's blank-line rules,
  plus reading the two largest Swift diffs.
- Removing the Material Icons notes may weaken Apache 2.0 attribution. The user accepted this; the icons'
  origin stays in git history.
- Losing the "why" behind non-obvious code (Keychain ad-hoc signing in `run-native-ios.sh`, backup exclusion
  XML, SQLCipher setup). The user accepted this; git history keeps it, and CLAUDE.md already documents
  backups and SQLCipher.
- The native builds need macOS + Xcode and a simulator. If one is not available, it is reported as skipped,
  not as passed.
